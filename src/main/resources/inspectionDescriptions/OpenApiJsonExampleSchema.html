Reports an inline example or default value in a JSON OpenAPI/Swagger spec that doesn't match the schema it belongs to: a schema's own example/default (and, in OAS 3.1, its examples array), a parameter or header example/examples, or a JSON media type example/examples.

The same kind of check as Spectral's oas3-valid-schema-example / oas3-valid-media-example and Redocly's no-invalid-schema-examples / no-invalid-media-type-examples, with no CLI or account required. Checked: type (including OAS 3.1 type arrays with "null" and OAS 3.0 nullable), enum, const, required, properties, items, minimum/maximum, minLength/maxLength, through local $refs in either format.

Deliberately never reported, rather than guessed:

  • Schemas using allOf, oneOf, anyOf, not or if/then/else, and $refs that don't resolve to a local file.
  • A missing required property that is readOnly or writeOnly.
  • Examples of non-JSON media types (XML, plain text), and a top-level "example": null.
